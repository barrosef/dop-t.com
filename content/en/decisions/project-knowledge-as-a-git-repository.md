## What was on the table

The owner's expectation, stated plainly on 2026-09-03: every document that
serves as the agent's knowledge — memories, context, specs, plans — is
available to *any* demand of the project the moment its sandbox comes up.
No sends, no requests, no config maps. From the agent's point of view the
content simply exists, shared and collaborated between agents.

Two attempts had preceded this, and both were the wrong kind. **A ConfigMap
projected as a volume** — config, not data; it lives in etcd and caps at one
megabyte. Rejected on sight. **A per-demand volume filled by a loader pod
pushing a tarball over a WebSocket, mounted read-only** — a transport, per
demand, read-only, rewritten at every resume: the opposite of shared.

The obvious next step, a per-project volume, failed on two facts: the local
cluster refuses read-write-many volumes, and a shared filesystem has no idea
*who* changed a file — the one thing the event-log decision requires this
platform to always know.

Then the owner named it: **versioned in git.** Instead of sharing a volume,
share a repository.

## The paths we weighed

**A read-write-many volume per project.** The local storage refuses it;
managed filers would provide it; and it still has no attribution. Git has
attribution built in.

**Object storage mounted as a filesystem.** Zero copies, and the storage the
platform already uses. But no driver on the local clusters, last-writer-wins
semantics, and versioning that gives history without authorship. It remains
the right shape for large binaries, which a repository is bad at.

**The user's own provider as the primary.** It requires integrating a
provider *before* a project can hold knowledge — contradicting "born under
the hood" — and puts the user's credential in the sandbox's path. It survives
as the mirror.

## What we chose, and why

**The knowledge lives in the project's root repository**, born with the
project in a git server the platform runs. Rules, repository maps, memories,
and each demand's spec, plan and context are files in it, and the manifest at
the top is generated by the platform on every push — a manifest that drifts
from the tree is worse than none.

**Every sandbox clones it; agents write by committing.** The clone is a
working copy, read-write; sharing between demands is push and pull; a
conflict is git's conflict, and one the agent cannot resolve becomes an
attention item. How a commit is attributed is [ADR-0003](../organization-credential-human-authorship/)'s
rule and is not repeated.

**The sandbox authenticates with a token that opens exactly one
repository** — per demand, short-lived, scoped to that project, delivered
as a projected file and never as an environment variable, which every child
process inherits. It is the only credential the sandbox holds, and it is
acceptable because of what it opens: the agent's own workbench, not a third
party's key.

**The user's remote is a mirror**, attachable at any time: the platform's
repository stays primary and pushes onward with the user's credential from
the vault, which the sandbox never sees. No two-way sync in v1 — that is a
conflict engine nobody asked for.

**Every push is an event**, carrying the author, the paths and the commit —
what regenerates the manifest, feeds the timeline, and makes the lessons
loop exist: a demand's findings become the project's memory by the agent
writing them where the next agent will read them.

## What it cost

A stateful component to run — a git server with storage and backup — the
price of "born under the hood", and the platform already runs Postgres and
NATS the same way. `git` in the devbox image. The sandbox contract's
guarantees rewritten: the knowledge path became writable, persistent across
resume and across demands, and fenced per project. The mechanism built on
the two previous days was removed. And the rule that fell out: text in git,
bytes in the bucket.

## Since then

It was built the same day and proven on both executors, Docker and
Kubernetes: the git server, per-demand tokens, the clone at provisioning,
the push fan-out and the mirror. The remaining half is the surface — the
cockpit's view of the shelf.
